# 规划 DNAKit 任务

生成一份可供用户审阅、并可由后续 Codex 会话执行的计划。本 Skill 只负责调查、规划和保存经确认的计划，不执行分析。

用户只需描述任务目标，例如 `$dnakit-plan 下载 hg38 参考基因组并准备训练数据。`。无需让用户重复说明工具检索、关键问题、计划内容、验收标准或执行前暂停等流程规则。Codex 的 `/plan` 模式可选。

1. 弄清用户期望的结果、现有输入、工作目录和输出要求。在不改动任务数据的前提下调查。若 DNAKit MCP 可用，必须针对任务所需能力实际调用 `search_dnakit_tools` 查找候选，并对选定工具逐个调用 `describe_dnakit_tool`，核对完整工具名、必需参数、输入限制、依赖及副作用；相关的现成工作流可用 `search_dnakit_skills` 和 `read_dnakit_skill` 查找。若 MCP 不可用，说明无法完成 MCP 工具核对，并尽可能只读地查询本地 DNAKit 文档或 CLI；此时把拟用工具标为“待通过 MCP 验证”。不要编造工具名称，也不要把“已找到工具”说成“科学流程已经验证”。
   如果用户选择由 Codex 调用 DNAKit MCP 执行，就按这条路线写明实际前置条件。不要仅因附近示例用了 `run_agent()` 脚本、第三方模型或其 API 密钥，就把它们列为必需条件。只有选定的执行方式或具体工具确实要求模型凭据时，才写入该依赖。如果工具返回的数据量超出 MCP 适合传输的范围，应规划使用可用的 DNAKit API 在本地流式处理。
2. 找出会影响科研结果或执行方式的选择，例如物种与参考组装、坐标约定、数据来源和版本、输入格式、输出内容与位置、资源需求及验收标准。仅对无法从任务描述或现有证据确定的关键事项提出简短问题；适合给默认值时，说明依据。未回答的事项应明确标出。
3. 用用户的语言起草计划，包含目标与范围、已确认的决定和待确认的假设、输入来源及版本、已知校验值、输出文件、按顺序排列的步骤、重要结果的检查方法，以及需要停止或询问用户的条件。单独列出“步骤—工具”对应关系：每项 DNAKit 操作写明经过搜索和参数核对的完整工具名、调用入口、关键参数及已确定的值、输入与输出、依赖、副作用和验收方法；尚未确定的参数标为待确认，不填造数值。若某步改用本地 DNAKit API、脚本或其他工具，写明具体接口及原因。只列任务实际需要的工具，不罗列整个目录。保存的 Markdown 必须包含这些信息，不能依赖本次对话中的口头说明；尚未核实的事实要标明。
4. 向用户展示计划，等待其明确确认或提出修改，再把计划标为已批准或保存已批准的版本。即使 Codex 拥有完整文件权限且 `approval_policy = "never"`，仍需这次确认。规划期间不要下载大规模数据、安装软件、运行分析、调用有副作用的 DNAKit 工具或创建结果文件。
5. 用户确认最终计划后，无需再等一条保存指令；除非用户指定其他位置，将其保存为 `plans/<能说明任务的名称>.md`。在文件中记录确认及关键决定，并在末尾要求后续 Codex 会话重新检查前置条件、执行已批准步骤、验证输出；遇到新的重大选择时先询问用户。如果当前模式不能写文件，提供完整的已确认计划，等用户回到可写模式后再保存；不要声称文件已经存在。保存后结束本次规划。

后续会话中的执行请求是单独的一步。先读取已保存的计划，核对工具、输入和外部来源是否仍与计划一致，再按已批准的范围执行。如果重要前置条件发生变化，先请用户修订计划。
