# compared_models 使用方法

## 说明

- 本目录下模型代码已放到 `compared_models/` 中。
- 除 `GROVER` 外，其余 Git 仓库当前均为完整克隆，不再使用 `--depth 1` 的浅克隆方式。
- `Enformer` 的官方代码不是独立仓库，而是 `google-deepmind/deepmind-research` 里的 `enformer/` 子目录。
- 本地当前只保留 `lucidrains/enformer-pytorch` 这一套 PyTorch 版 `Enformer` 代码与 `EleutherAI/enformer-official-rough` 权重；官方 TensorFlow 代码目录与 SavedModel 权重当前都不在本地。
- `AlphaGenome` 官方分成两个仓库：
  - `alphagenome`：API / SDK
  - `alphagenome_research`：研究代码与可下载权重入口
- `Caduceus-Ph` 不是单独仓库，包含在 `caduceus` 仓库中。
- `GROVER` 由于官方主要通过 Hugging Face + Zenodo 分发，本地没有使用 `git clone`，而是直接下载了做分类/回归微调所需的最小集合：
  - 预训练模型权重与 tokenizer
  - 官方教程 notebook
  - 修订版 notebook
- `GROVER` 的 `tokenized_chromosomes/` 未下载，因为它们更适合需要染色体级 token mapper 的场景，不是一般序列级分类/回归微调的必需依赖。
- 已在 `visualdna` 环境实测通过本地目录加载 `GROVER` 的 tokenizer、`AutoModelForMaskedLM` 和 `BertForSequenceClassification`。

## eQTL / 双序列输入范式

- 本节总结的是各模型族在 `eQTL` 这类 `REF/ALT` 双序列输入任务中的常见处理方式。
- 这里的“范式”优先按当前仓库代码与对应论文中能确认到的实现口径归纳，不等价于所有论文都提供了现成、统一的官方训练脚本。
- `JanusDNA` 需要单独注意：论文描述更像 pair-input 任务，但当前本地仓库里的 `eQTL` 实现实际是 `ALT-only`，并没有显式把 `REF/ALT` 两条序列同时送进同一个下游头。

| 范式                                                       | 模型                                                                                           |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `REF/ALT` 分开编码 -> `concat embedding` -> 浅层分类器 | `Caduceus`、`HyenaDNA`、`NT-v2`、`Enformer`（按 `DNALongBench / Caduceus` 论文口径） |
| `REF/ALT` 分开预测 -> `ALT-REF delta score`            | `AlphaGenome`、`Evo2` zero-shot                                                            |
| 论文像 pair-input，但本地代码实际`ALT-only`              | `JanusDNA` 当前仓库                                                                          |
| 当前仓库没看到现成`eQTL` 双序列头，需要自己接            | `DNABERT-2`、`GROVER`、`LucaOne`、`GENERator`                                          |

## 每个模型的建议 chunk 长度

- 本节对应当前文档“长程优先默认 checkpoint 清单”里的那一组默认权重。
- 总原则：
  - 若 `L_task <= L_model`，则不切 chunk，直接整条输入。
  - 若 `L_task > L_model`，则按下表中的建议长度切 chunk。
  - 对 `token-based` 模型，优先按 `token` 长度切，不先强行换算成固定 `bp`。
- `DNABERT-2`、`NT-v2`、`LucaOne`、`GROVER` 更适合作为补充/适配表模型，不建议和原生超长上下文模型放在同一主表直接混排。

## 统一下游任务 benchmark 协议

- 本节给出当前项目推荐的主协议：`Native-context frozen linear probe benchmark`。
- 这套协议的目标是：保留每个模型的原生上下文能力，同时统一下游读出方式和训练方式。
- 脚本现在支持通过 `--finetune-method` 选择下游适配方式；默认仍是 `frozen_linear_probe`，即冻结预训练 `backbone`，只训练最后一层 `linear head`。
- 不再提供按模型自动选择微调方式的快捷入口；需要在每个模型允许的范围内显式传入 `frozen_linear_probe`、`full` 或 `ia3`。

### 0. 微调方式选择规则

| 模型            | 允许的`--finetune-method`        | 说明                                                                   |
| --------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| `DNABERT-2`   | `frozen_linear_probe` / `ia3`  | IA3 使用 Hugging Face PEFT；也可跑 frozen embeddings + linear probe。  |
| `NT-v2`       | `frozen_linear_probe` / `ia3`  | IA3 target 默认覆盖`key`、`value`、`output.dense`。              |
| `GROVER`      | `frozen_linear_probe` / `ia3`  | BERT-like 结构，IA3 target 默认同 BERT。                               |
| `LucaOne`     | `frozen_linear_probe` / `ia3`  | IA3 默认作用在`k_proj`、`v_proj`、`fc2`。                        |
| `GENERator`   | `frozen_linear_probe` / `ia3`  | Llama-like 结构，IA3 默认作用在`k_proj`、`v_proj`、`down_proj`。 |
| `Enformer`    | `frozen_linear_probe` / `ia3`  | 非标准 HF Transformer，`ia3` 实际走 IA3-like 线性缩放层。            |
| `HyenaDNA`    | `frozen_linear_probe` / `full` | 可做全量微调；显存不足时可退回 frozen embeddings + linear probe。      |
| `Caduceus-Ph` | `frozen_linear_probe` / `full` | 可做全量微调；显存不足时可退回 frozen embeddings + linear probe。      |
| `JanusDNA`    | `frozen_linear_probe` / `full` | 可做全量微调；仍可使用 frozen embeddings + linear probe 做公平主表。   |
| `Evo2`        | `frozen_linear_probe`            | 只允许 frozen embeddings + linear probe。                              |
| `AlphaGenome` | `frozen_linear_probe`            | 只允许 frozen embeddings + linear probe。                              |

- `frozen_linear_probe`：冻结 backbone，只训练线性任务头，是主表默认方式。
- `full`：解冻 backbone 和线性任务头，做全量微调；仅 HyenaDNA、Caduceus-Ph、JanusDNA 开放该方式。
- `ia3`：优先按 Hugging Face PEFT 的 `IA3Config/get_peft_model` 注入 IA3；仅 DNABERT-2、NT-v2、GROVER、LucaOne、GENERator、Enformer 开放该方式，其中 Enformer 使用 IA3-like 线性缩放层。
- 可用 `--ia3-target-modules` 和 `--ia3-feedforward-modules` 覆盖默认 IA3 注入层，多个模块名用英文逗号分隔。

### 1. 输入长度与分块

- 每个任务的输入长度固定为真实任务长度 `L_task`，不因为模型不同修改任务原始序列长度。
- 每个模型使用自己的原生上下文长度 `L_model`，优先取该 checkpoint 对应论文或官方实现里最常用、最稳定的默认长度。
- 若 `L_task <= L_model`，则整条序列直接输入模型。
- 若 `L_task > L_model`，则按该模型自己的 `L_model` 切成多个 chunk。
- 第一版固定：
  - `chunk_size = L_model`
  - `stride = L_model`
  - 即不重叠切分，优先保证实现简单、稳定、可复现。
- 最后一个不足长度的 chunk 允许使用右侧 `padding` 或 `N` 补齐；后续做 chunk 内读出时只统计有效区域。

### 2. 每个 chunk 的表示提取

- 对普通序列语言模型，chunk 级 token 读出统一支持两种可选方式：
  - `mean`
  - `last token`
- 当前 `--token-readout auto` 对已接入的 token-based 对比模型默认使用 `mean`；若要使用最后一个有效 token 表示，需要显式传入 `--token-readout last`。
- 建议在同一轮 benchmark 中固定一种 `token readout` 设置，不要对不同模型随意混用。

| 模型类型         | 每个 chunk 的表示规则                                                                                                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `encoder-only` | 支持两种读出：1.`mean`：取 token hidden states，对 `valid tokens` 做 `mask-aware mean pooling`；`valid tokens` 默认指非 `pad`，并尽量排除 `CLS / SEP / BOS / EOS` 等特殊 token。2. `last token`：取每个 chunk 的 `last valid token hidden state`，即最后一个非 `padding` 位置的 hidden state，而不是盲目取张量最后一位。 |
| `decoder-only` | 同样支持两种读出：1.`mean`：对每个 chunk 的 `valid tokens` 做 `mask-aware mean pooling`。2. `last token`：取每个 chunk 的 `last valid token hidden state`。如果使用 `last token`，这里始终指最后一个非 `padding` 位置，而不是张量最后一位。                                                                                  |
| `Enformer`     | 对 chunk 前向，取`return_embeddings=True` 返回的 `embedding`，再对 bin 维平均，得到 chunk 向量。主表默认不用 final output tracks。                                                                                                                                                                                                     |
| `AlphaGenome`  | 对 chunk 前向，取`embeddings_1bp`，再对位置维平均，得到 chunk 向量。主表默认不用 `predictions_1bp / predictions_128bp`。                                                                                                                                                                                                               |

### 3. 多 chunk 聚合

- 若一个样本被切成多个 chunk，设各 chunk 表示为 `h_1, h_2, ..., h_n`。
- 序列级表示统一定义为：
  - `z = mean(h_1, h_2, ..., h_n)`
- 这里对所有 chunk 直接平均，不做加权平均。

### 4. 统一任务头

- 单序列分类：
  - `sequence -> backbone -> chunk representations -> chunk mean -> linear`
- 单序列回归：
  - `sequence -> backbone -> chunk representations -> chunk mean -> linear`
- 双序列任务：
  - 分别得到 `z_ref` 和 `z_alt`
  - 最终输入特征统一为：
    - `cat(z_ref, z_alt, z_alt - z_ref) -> linear`

### 5. 参数更新与损失函数

- 主表默认使用 `frozen_linear_probe`：
  - 冻结整个 `backbone`。
  - 只训练最后一层 `linear head`。
  - 不加 `MLP`、`LoRA`、`adapter`，也不解冻最后几层。
- 补充实验可使用 `full` 或 `ia3`：
  - `full` 解冻 backbone 和线性任务头。
  - `ia3` 冻结原始 backbone 权重，仅训练 IA3/IA3-like 缩放参数和线性任务头。
  - `Evo2` 与 `AlphaGenome` 不进入 `full` 或 `ia3`，始终只做 `frozen_linear_probe`。
- 分类任务：
  - 二分类：`BCEWithLogitsLoss` 或二类 `CrossEntropyLoss`
  - 多分类：`CrossEntropyLoss`
  - 多标签：`BCEWithLogitsLoss`
- 回归任务：
  - 默认使用 `MSELoss`

### 6. 训练设置

- 默认训练超参：
  - `optimizer = AdamW`
  - `lr = 1e-3`
  - `batch size = 16`
  - `weight decay = 1e-4`
  - `max epoch = 100`
  - `early stopping patience = 30`
  - `warmup ratio = 0.1`
  - 学习率调度：`cosine annealing`，最终学习率衰减到初始学习率的 `0.1` 倍
  - `random seed = 42`
- `batch size` 允许因显存限制做最小必要调整；若差异较大，建议使用 `gradient accumulation` 保持有效 batch size 尽量接近。
- 若使用 `early stopping`，则同一轮 benchmark 中应统一开启或统一关闭。

### 7. 专家模型的主表解释

- `Enformer` 主表默认使用 `embedding`，不直接使用 final output tracks。
- `AlphaGenome` 主表默认使用 `embeddings_1bp`，不直接使用 `predictions_1bp / predictions_128bp`。
- 因此在主表中，这两类模型应被解释为：
  - `expert backbones under frozen linear probe`
- 这不等价于它们各自原论文中的最佳任务专用用法。

## 本地权重目录约定

- `weights/` 目录下只保留每个模型族 1 套“长程优先默认权重”。
- 如果官方仓库同时提供 `pytorch_model.bin`、`model.safetensors`、`jax` 等多套格式，本地默认只保留 1 套主权重，避免重复占用磁盘。
- `JanusDNA` 同时保留了原始压缩包和解压目录，便于后续校验。
